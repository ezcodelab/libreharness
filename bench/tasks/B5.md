# B5 Docs: document a new flag and fix a stale link

| Field | Value |
|---|---|
| Category | Docs |
| Comparisons | A, B |
| Time limit | 30 minutes |
| Token cap | recorded in the run manifest |
| Fixture | `bench/fixtures/b5-docs/` (to be built) |
| Fixture commit | set when the fixture is frozen |
| Allowed tools | the arm default tool set; hidden tests stay outside the workspace |

## Fixture idea

A small command line tool with a working `--dry-run` flag that is missing from
the docs. The README shows an old example that fails after a recent rename, one
link points to a removed page, and `docs/usage.md` omits the new flag. The
fixture has a docs lint command and a smoke test that runs the examples. Under
600 lines including docs, no external services.

## Prompt

```text
Document the --dry-run flag in docs/usage.md and the README. Update the example
that uses the old command name so it runs again, and fix the stale link. Keep
the writing consistent with the rest of the docs, and do not change code.
```

## Acceptance

- `--dry-run` is documented with its behavior and one working example.
- The README example uses the current command name and runs successfully.
- The stale link is removed or points to an existing page.
- No stale text about the old command name remains in the touched docs.
- Docs lint passes and the example smoke test passes.
- No code files change.

## Hidden checks

Not visible in the agent workspace.

- Docs lint over `README.md` and `docs/`.
- Link check confirms every relative link resolves.
- Extract fenced commands from the touched docs and run them in the fixture.
- Search for the old command name and fail if it remains in user-facing docs.
- Confirm the diff contains no source code changes.
