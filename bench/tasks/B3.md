# B3 Refactor: deduplicate validation without behavior change

| Field | Value |
|---|---|
| Category | Refactor |
| Comparisons | A, B |
| Time limit | 30 minutes |
| Token cap | recorded in the run manifest |
| Fixture | `bench/fixtures/b3-validation/` (to be built) |
| Fixture commit | set when the fixture is frozen |
| Allowed tools | the arm default tool set; hidden tests stay outside the workspace |

## Fixture idea

A small signup service with two nearly identical validation paths, one for
email and one for username. Both trim, check length, check an allowlist of
characters, and return the same error codes in a different order. The fixture
has a characterization suite and a public function that returns normalized
values. Under 800 lines, no external services.

## Prompt

```text
The email and username validators duplicate the same rules and have drifted.
Refactor them to share one validation path without changing any public
behavior, error code, or error order. Keep the exported function names and
signatures. Run the existing tests and add characterization tests only where
behavior is currently untested.
```

## Acceptance

- The duplicated rule logic exists once.
- Exported names and signatures are unchanged.
- Error codes, error order, and normalized values are unchanged.
- Existing tests pass.
- New characterization tests cover the previously untested edge cases.
- No unrelated files change.

## Hidden checks

Not visible in the agent workspace.

- Snapshot comparison of normalized output and error codes for a fixed input
  corpus before and after the refactor.
- Empty, whitespace-only, maximum-length, and disallowed-character inputs.
- Error order matches the original implementation exactly.
- The old duplicated helper is gone or delegates to the shared path.
- The diff touches only the validation module and its tests.
