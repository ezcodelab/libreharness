## Fixture idea

A small report service with a parser for command line and environment settings,
a service layer with a fixed cache TTL constant, a README, and tests. Add a
`cache_ttl_seconds` setting that can be set by flag or environment variable,
is validated, and reaches the service. The fixture has one integration test
harness and no external services. Under 1,200 lines.

## Prompt

```text
Add a cache TTL setting to the report service. It must be configurable with
--cache-ttl-seconds and REPORT_CACHE_TTL_SECONDS, with the flag taking
precedence. Validate that the value is a positive integer, pass it through to
the cache in the service layer, document it in the README, and add unit and
integration tests. Keep the existing default behavior when the setting is not
provided.
```

## Acceptance

- The flag and environment variable both set the TTL.
- The flag takes precedence over the environment variable.
- Zero, negative, and non-integer values fail with a clear error.
- The existing default TTL applies when neither source is set.
- The service layer uses the configured value, not a constant.
- The README documents both sources, precedence, and the default.
- Unit and integration tests cover the parser, precedence, validation, and the
  service path.
- Existing tests pass.

## Hidden checks

Not visible in the agent workspace.

- Flag only, environment only, both set, and neither set.
- Invalid values are rejected before the service starts.
- Integration test observes the configured TTL reaching the cache.
- The default is unchanged when the setting is absent.
- README examples run and match the implemented names.
- The diff touches parser, service, docs, and tests.
