# B7 Security: path traversal in a file download

| Field | Value |
|---|---|
| Category | Security |
| Comparisons | A, B, C |
| Time limit | 30 minutes |
| Token cap | recorded in the run manifest |
| Fixture | `bench/fixtures/b7-download/` (to be built) |
| Fixture commit | set when the fixture is frozen |
| Allowed tools | the arm default tool set; hidden tests stay outside the workspace |

## Fixture idea

A small file sharing service. `GET /files/<name>` joins the requested name to a
per-user upload directory with `os.path.join` and serves the result. A crafted
name such as `../other-user/secret.txt` escapes the directory, and an absolute
name replaces the base path entirely. The fixture includes two users with
separate directories and a test client. Under 900 lines, no external services.

## Prompt

```text
GET /files/<name> lets a user read files outside their own upload directory.
Fix the path traversal without breaking legitimate downloads. Keep the route
and response format unchanged, and add tests for the exploit and for normal
access.
```

## Acceptance

- Traversal with `..`, encoded traversal, and an absolute path is blocked.
- Legitimate files in the user's own directory still download.
- A file belonging to another user is not readable.
- The response for a blocked request does not leak filesystem paths.
- The route and success response format are unchanged.
- New tests cover the exploit and normal access.

## Hidden checks

Not visible in the agent workspace.

- Requests for `../other-user/secret.txt`, `..%2fother-user%2fsecret.txt`, and
  an absolute path all fail without returning file contents.
- A symlink inside the user directory that points outside is not followed.
- A legitimate nested file inside the user directory still downloads.
- Error responses contain no absolute path or stack trace.
- Run the original suite unchanged.
