# B4 Review: seeded diff with three defects

| Field | Value |
|---|---|
| Category | Review |
| Comparisons | A, B, C |
| Time limit | 30 minutes |
| Token cap | recorded in the run manifest |
| Fixture | `bench/fixtures/b4-review/` (to be built) |
| Fixture commit | set when the fixture is frozen |
| Allowed tools | the arm default tool set; hidden tests stay outside the workspace |

## Fixture idea

A small invoice service with a prepared diff that adds an admin endpoint, a
database write, and a test. The diff contains exactly three seeded defects:
an authorization check that trusts a client-supplied role header, a write path
that has no rollback when a later step fails, and a test that depends on wall
clock time and is flaky near midnight. The rest of the diff is ordinary,
working code. The fixture is delivered as a repository plus `review.diff`.

## Prompt

```text
Review the pending diff in review.diff against the repository. Report only
defects that could affect correctness, security, or reliability. For each
finding, give the file and line, explain the failure mode, and suggest a fix.
Do not edit code. Do not report style preferences or speculative concerns.
```

## Acceptance

- All three seeded defects are reported with the correct file and line.
- Each finding explains a concrete failure mode, not a generic warning.
- No invented blocker is reported as a defect.
- The agent does not edit code.
- Style-only comments are not counted as findings.

## Hidden checks

Not visible in the agent workspace.

- Two reviewers independently score the report against the rubric: auth bypass,
  missing rollback, flaky test. Each is 0 or 1, for `defects_found` 0 to 3.
- Each finding must name the correct file and a line within the seeded hunk.
- A finding that is real but not seeded is recorded as a false positive unless
  both reviewers agree it is a genuine defect.
- Any code edit fails the review task.
- Reviewers agree on the score before the arm label is revealed.
