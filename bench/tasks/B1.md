# B1 Bug fix: duplicate at a page boundary

| Field | Value |

## Fixture idea

A small task list service with cursor pagination over a stable sort key. When a
page ends exactly on an item that shares a sort key with the next item, the
cursor comparison uses the wrong tie-breaker and the next page repeats one
item. The existing suite covers ordinary pages but not the boundary. The fixture
has a deterministic in-memory store, under 1,000 lines, no external services.

## Prompt

```text
The task list endpoint sometimes returns the same task on two consecutive
pages. Reproduce the problem, fix it, and keep the existing behavior and API
unchanged. Run the existing tests when you are done. Do not change the public
response shape.
```

## Acceptance

- Consecutive pages contain no duplicate item.
- The item at the page boundary appears exactly once across the full traversal.
- Ordering is stable and matches the documented sort key plus tie-breaker.
- Empty pages and the final page behave correctly.
- Existing tests pass.
- The public response shape is unchanged.

## Hidden checks

Not visible in the agent workspace.

- Walk the full collection with page sizes 1, 2, and 3 and assert each item
  appears exactly once.
- Seed several items with an identical sort key and assert the tie-breaker is
  stable across pages.
- Request a page past the end and assert an empty list, not an error.
- Request the exact last page and assert no trailing empty page.
- Run the original suite unchanged.
